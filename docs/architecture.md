# Architecture & Network Topology

本ドキュメントでは、本同期システムにおけるネットワークトポロジ、暗号化通信、認証・認可基盤の設計詳細について解説します。

---

## 1. ネットワーク分離とルーティング設計

本システムは、家庭内 LAN の既存ルーター（民生用機）に一切のポート開放（Port Forwarding）を行わず、完全な閉域網（Overlay Network）として完結するように設計されています。

```
[ 外出先クライアント / 各種端末 ]
           │
           │ (Tailscale 暗号化トンネル / WireGuard)
           ▼
┌─────────────────────────────────────────────────────────────┐
│ 宅内オンプレミス基盤 (Proxmox VE ホスト)                      │
│                                                             │
│   ┌───────────────────────────┐   ┌───────────────────────┐ │
│   │ LXC 100: Nextcloud Hub    │   │ LXC 105: vdirsyncer   │ │
│   │ IP: 100.82.15.31 (Tailnet)│   │ IP: 100.x.y.z (Tailnet)│ │
│   │ Domain: ncp.example.com   │   │ RAM: 256MB            │ │
│   │ Web Server: Apache 2.4    │   │ Engine: vdirsyncer    │ │
│   └─────────────▲─────────────┘   └───────────┬───────────┘ │
│                 │                             │             │
│                 └───────(Tailscale 経由)───────┘             │
└───────────────────────────────────────────────┬─────────────┘
                                                │ (HTTPS / OAuth 2.0)
                                                ▼
                                    [ Google Calendar API ]
```

### なぜ生 IPv6 直打ちを避けたのか
* 一般家庭の光回線環境において、ISP から割り当てられる生グローバル IPv6 アドレス（`2400:...` 等）を直接サーバーに紐付けると、民生ルーターのステートフルパケットインスペクション（SPI）やパケットフィルタの仕様次第で、サーバーの 443 番ポートが全世界に露出する危険性がある[cite: 3]。
* NAT が存在しない IPv6 環境下での露出事故を避けるため、CGNAT 空間（`100.64.0.0/10`）を利用する Tailscale のプライベート IPv4 アドレス（`100.82.15.31`）を通信の終端とした[cite: 3]。

## 2. DNS-01 チャレンジによる完全閉域 SSL/TLS の実現

通常、Let's Encrypt 等の公的認証局から SSL/TLS 証明書を取得する際は HTTP-01 チャレンジ（80番ポートへの疎通）が用いられますが、ポート開放を行わない本環境では利用できません[cite: 3]。

そのため、Cloudflare API を用いた **DNS-01 チャレンジ（ACME）** を採用しています[cite: 3]。

1. **ドメイン設定**:
   Cloudflare DNS 上に `A` レコード（`ncp.example.com` -> `100.82.15.31`）を「DNS Only（プロキシ無効 / グレー雲）」として登録[cite: 3]。
2. **認可トークンの最小権限化**:
   `certbot` 用の Cloudflare API トークンは、特定ゾーン（`example.com`）の「DNS 編集権限」のみにスコープを限定[cite: 3]。
3. **証明書の発行フロー**:
   `certbot` が Cloudflare API を経由して一時的な `_acme-challenge.ncp.example.com` TXT レコードを注入し、Let's Encrypt 側でドメイン所有権を検証[cite: 3]。
4. **自動更新**:
   90日の有効期限に対し、デプロイフック（`reload-apache.sh`）を仕込むことで無停止かつ手動介入ゼロで証明書を自動更新[cite: 3]。

## 3. 非特権コンテナの権限境界 (LXC Security Model)

`vdirsyncer` をホストする LXC コンテナは、セキュリティ上の観点から **非特権コンテナ（Unprivileged Container）** として稼働させています[cite: 3]。

* 非特権コンテナ内部の `root`（UID 0）は、Proxmox ホスト側では一般ユーザー（UID 100000+）にマッピングされており、万が一コンテナが侵害されてもホストOSへの特権昇格を防止[cite: 3]。
* Tailscale 稼働に必要な `/dev/net/tun` デバイスへのアクセスのみをホスト側設定（`/etc/pve/lxc/105.conf`）でピンポイントに許可することで、セキュリティ境界とネットワーク要件を両立[cite: 3]。
